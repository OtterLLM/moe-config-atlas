Definitions

E / k / s
Number of routed experts / routed experts selected per token / number of shared experts. For models whose layers differ, the mean or mode is used and the table marks it ≈.
E/k
Routing sparsity, counting routed experts only.
Expert activation A
(k + s) / (E + s), shared experts included.
Parameter activation ratio
Active params / total params, both taken from the model card or tech report (they are not in the config).
G
2d / dexpert, where d is the hidden size. Compared with the standard FFN width of 8d/3, G≈2.7 means "one expert = one dense FFN".
d/L
Aspect ratio: hidden size divided by the number of token-mixer layers (attention, linear-attention or Mamba layers). LongCat has two attention sub-layers per layer, counted as two layers.
Attention width ratio
Global-layer query heads × per-head Q·K dim, divided by d_model. A Llama-style design with heads × head dim = d gives 1; MLA's Q·K dim is the no-position part plus the RoPE part (128 + 64 for DeepSeek V3), and the DeepSeek V4 family uses 512 per head, hence 6.4–9.1. The larger the ratio, the wider attention is relative to the residual stream.
Q/KV
How many query heads each KV head serves in a global layer (the GQA group size); the larger, the cheaper the KV cache. Not applicable to MLA, which caches a compressed latent.
RoPE dimension share
The fraction of each head's dimensions that get RoPE in global layers. 1 means all dimensions; 1/4, 1/3 and similar are partial RoPE, with the remaining dimensions carrying no position; 0 is recorded as NoPE, leaving position information to sliding-window, chunked, linear or Mamba layers, with exceptions in parentheses (Inkling uses a learned relative-position logit instead; North Mini Code's first global layer is a dense layer and still gets RoPE). Mistral Large 4 has one layer in every 4 without RoPE, so its NoPE column reads "18/72 layers". For MLA it is computed as RoPE dim / Q·K dim.
Share of global-attention layers
The fraction of token-mixer layers whose KV cache grows with context (full, MLA, DSA, sparse or compressed attention). Linear attention, Mamba and short-convolution state sizes are fixed, and sliding-window layers and Llama 4's chunked layers only cache the tokens in the window or chunk.
KV cache / token
The bf16 KV that each extra token adds when the context is long enough: number of global layers × K and V dims per token per layer × 2 bytes. MLA is computed from kv_lora_rank + RoPE dim; DeepSeek V4's compressed layers are amortized per token by their compression ratio (CSA stores one entry per 4 tokens, HCA one per 128). Linear-layer state, sliding-window caches and sparse-attention index keys are not counted; DeepSeek V4.1 changed how the compression config is written and is not computed for now.
Attention
Inferred from the layer-type fields in config.json (layer_types, kda_layers, full_attention_interval, etc.); it only counts the kinds and number of token-mixer layers, so defer to the tech report for details.
Structural features
Recognized from the fields of config.json. Parts the config does not spell out (Qwen3's QK-norm, gpt-oss's sink, each vendor's routing scoring function) are checked against the modeling code in transformers 5.21 and the vendors' repositories; the rules are in ARCH in scripts/hfconfig.py. What a config does not disclose or show is recorded as "?" and left out of adoption rates.
Structural fingerprint
Shape numbers are colored by quintile over all configurations and only indicate relative size within the included set; the values in the cells match the full table. When grouped by tier, the first row of each tier, and when aggregated by vendor, each cell, shows the number of configurations that use the feature / the number where it can be determined; the shape numbers in a tier summary row are the median of that tier.
Linear attention
Token mixers with a fixed state size: Gated DeltaNet (GDN), Kimi Delta Attention (KDA), MiniMax and Ling's Ring linear, Lightning Attention in Ling 2.5 / 2.6, Mamba-2, and LFM2's gated short convolution (shown as "gated conv" in the table).
Sparse attention
Each query sees only part of the KV: DeepSeek's DSA, LongCat's LSA (the DSA top-k budget always keeps the first and the most recent tokens, and reuses indices across layers), Qwen3.8-Flash-Next's QSA, Step-5's CSA, MiniMax M3's block sparsity, Ring-mini-sparse's MoBA (KV is split into blocks and each query reads only a few selected blocks), and DeepSeek V4's compressed attention (CSA + HCA). Most layers of ERNIE 5.5 Flash are HCA, with an MLA+DSA layer every 7 layers, recorded as DSA+HCA.
Output gate
The output of a softmax-attention layer is multiplied by a gate computed from the input (Gated Attention; mostly sigmoid, Laguna uses softplus). One scalar per head is recorded as "per-head", one per element as "per-element", and a config that does not say is marked ✓. Gates built into linear-attention layers do not count.
Sink / QK-norm
A sink is one learnable logit per head that lets attention "look at nothing"; QK-norm applies RMSNorm to each head's Q and K (Llama 4 Scout and ZAYA1 use L2 normalization, Scout only in RoPE layers; Ling 2.5 / 2.6 only in Lightning layers). Normalizing MLA's low-rank latents does not count as QK-norm.
K=V / cross-layer KV / index reuse
K=V: K and V share one projection and only one copy is cached. Cross-layer KV: later layers read the KV of an earlier source layer directly and store none of their own. Index reuse: the top-k selection of sparse attention is shared by several layers (IndexShare, cross-layer indices), saving the indexer's computation.
QKV short convolution
Q, K and V of softmax attention first pass through a causal depthwise convolution along the sequence (introduced by Primer). Inkling adds a 4-tap convolution on K, V and on the outputs of both sub-layers; ZAYA1's CCA convolves Q and K in the compressed latent space. Short convolutions built into linear-attention layers do not count.
Length scaling (SSMax)
Global layers scale the query up with the log of the position so that attention does not flatten out over long contexts (Scalable-Softmax). Llama 4 calls it temperature tuning; Beam and Inkling also use it only in global layers without RoPE; Mistral Large 4 uses it in every layer with per-head learned coefficients (recorded as "per-head learnable").
Hyper-connections
The residual stream is widened to n streams that are mixed with learnable weights (Hyper-Connections); mHC constrains the mixing matrix to be doubly stochastic with Sinkhorn; iHC is Hy4's formulation.
AttnRes
Attention Residuals: each layer's input is an attention-weighted combination of the outputs of earlier layers (by block), replacing the fixed residual sum.
Residual gate / post-norm
Residual gate: the sublayer output and the residual are added with per-channel learnable weights (Muse Spark uses a variance-preserving gate, ZAYA1 a pair of scales). Post-norm: the sublayer output passes through one more norm; one before and after is called sandwich, one only after the residual addition is Post-LN, and A.X K1 adds it only after the MoE output.
GatedNorm / parallel block
GatedNorm: the RMSNorm output is multiplied by a low-rank sigmoid gate computed from it; the cell shows the rank. Parallel block: attention and the FFN read the same input and their outputs are added back to the residual together (Cohere).
Shared-expert gate
The shared expert's output is multiplied by a gate computed from the input: the Qwen family uses a separate sigmoid gate, and Inkling has the router also score the shared expert ("routing-weighted").
Zero-compute experts
Empty experts that compute nothing; when the router picks one, that token effectively uses one fewer expert (LongCat's zero-compute experts, ZAYA1's skip experts). The cell shows the count.
Routing
The scoring function (softmax, sigmoid, sqrtsoftplus), the auxiliary-loss-free expert bias (updated by quantile is recorded as "quantile", training-only and absent from the weights as "training only"), grouped routing that first picks groups and then experts, and hash routing that assigns experts by token-id hash in the first few layers.
FFN activation / clamp
Mostly SwiGLU; Gemma 4 uses GeGLU, gpt-oss and MiniMax M3 use SwiGLU with clamping and offset (SwiGLU-OAI), Nemotron 3 uses ReLU², and Kimi K3 uses SiTU. Clamping caps the SwiGLU output at an upper limit, with parentheses meaning only some layers; SiTU soft-clamps with β·tanh(x/β).
MTP
The number of layers in the multi-token-prediction module. If the config does not say, the mtp layers are counted from the weight index (for gated repositories, the index of a public copy); when it cannot be read, "?".
softcap
Soft clipping of the output logit through c·tanh(x/c); the cell shows c.
N-gram memory
A large embedding table looked up with hashed n-grams: Engram and Qwen3.8-Flash-Next inject it in middle layers, LongCat adds it to the input embedding.
Design details compared
For each position (attention output gate, routing weights, residual addition, norms, etc.), the variants that appear among the included models are listed, with formulas written from the modeling code; what neither the config nor the code reveals is recorded as "details not disclosed". "Related work" are variants from papers or training configs that no included model uses yet. The list and the matching rules are in details.yaml, and the build checks that every model falls under some variant.
Frontier technique tracker
The list is in techniques.yaml; each entry has its earliest source, the result of independent experiments, and links. Adoption counts are computed automatically from the structural features; for techniques a config cannot show (optimizers, loss functions), only what the tech report states is listed, and otherwise the entry is left empty rather than guessed.
Config source
When a repository requires access approval, the config is taken from the corresponding default config in transformers or from a public copy, archived under configs/ in this repository and noted in the table details.
Leaderboard scores
Scores from two public leaderboards, used to rank configurations and re-read on every build. ECI is Epoch AI's Epoch Capabilities Index, a single number fitted to dozens of benchmarks such as GPQA Diamond, SWE-bench Verified, HLE and FrontierMath, putting open and closed models on the same scale; Arena is the arena.ai (formerly LMArena) text leaderboard, from users' pairwise votes on anonymous answers, using the default style-control board, which is closer to chat experience than to benchmarks. Names on the leaderboards are matched against each configuration's model name, repository name and the versions of the same architecture (the rules are in scripts/bench.py, and unmatched ones are written in bench.yaml); for one architecture the highest score is taken and the version it came from is noted: those versions differ only in post-training, and the architecture is the same. A score reflects the version at the time of inclusion, and small and regional models are covered less. Both boards' data are used under CC BY 4.0. Artificial Analysis's intelligence index is not included: its terms do not allow publishing the scores as a table or data file.
Normalized average
The two boards have different scales (ECI is roughly 120–160, Arena is an Elo rating around 1300–1500) and cover different configurations, so each board is first converted to z-scores: (score − mean) ÷ standard deviation, with the mean and standard deviation computed over the configurations that have a score on both boards, so a configuration on only one board is compared with the same group. Each configuration averages the boards it has, and finally the highest on this site is set to 100 and the lowest to 0. A configuration on only one board is flagged (for example "Arena only"), and its average represents that one board only. Configurations on neither board are ranked last.
Tiers
By total params: small ≤ 50B, medium 50–500B, large ≥ 500B.
Scope
Open-weight MoE models first uploaded in 2025 or later. Versions with exactly the same architecture (attention, MoE, layer count and all dimensions, modality, vocabulary) that differ only in post-training, context length, MTP layers or weight format are merged into one row, with the model name showing the newest version; any architectural difference gets its own row. Every build reads each version's config.json to check this.
Data comes from each model's config.json and model card on Hugging Face; leaderboard scores come from Epoch AI and the Arena text leaderboard (CC BY 4.0). Please report errors in GitHub issues.
